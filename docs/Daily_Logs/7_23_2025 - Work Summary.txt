## Debugging Attempts That Didn't Work

1. **Attempt to Add GAME_PHASE_MISDEAL**
   - **What was tried**: Added `GAME_PHASE_MISDEAL` to constants.js
   - **Why it failed**:
     - Required updating 12+ files referencing game phases
     - Added complexity without real benefit
     - Broke existing phase transition logic
   - **Error**: `TypeError: Cannot read property 'MISDEAL' of undefined`

2. **Global Mocking of validateBid**
   - **What was tried**: `mock.method(validationCore, 'validateBid', mockFn)`
   - **Why it failed**:
     - ES modules prevent redefinition of exported bindings
     - Mock was not being called in test execution
   - **Error**: `TypeError: Cannot redefine property: validateBid`

3. **Direct Mock Assignment**
   - **What was tried**: `validationCore.validateBid = mockFn`
   - **Why it failed**:
     - ES modules create read-only bindings
     - Assignment in test didn't affect imported module
   - **Error**: `TypeError: Cannot assign to read only property 'validateBid'`

4. **Dynamic Import with Mocks**
   - **What was tried**:
     ```javascript
     const module = await import(`../../../src/game/phases/biddingPhase.js?${Date.now()}`);
     ```
   - **Why it failed**:
     - Cache busting didn't work as expected
     - Made tests flaky and hard to debug
     - Didn't solve the core mocking issue

5. **Test Framework Replacement**
   - **What was tried**:
     - Added jest as dev dependency
     - Created jest.config.js
     - Converted tests to use jest.mock()
   - **Why it failed**:
     - Required major test rewrites
     - Caused conflicts with existing node:test patterns
     - Added significant build complexity

6. **Redundant Phase Validation**
   - **What was tried**:
     ```javascript
     if (gameState.phase !== GAME_PHASES.ORDER_UP_ROUND2) {
       throw new InvalidPhaseError('callTrump decision', GAME_PHASES.ORDER_UP_ROUND2);
     }
     ```
   - **Why it was removed**:
     - Duplicated validation in validateBid
     - Made error messages less specific
     - Added maintenance overhead

## Lessons Learned
- ES modules have strict rules about mocking
- Simpler solutions are often better
- The existing implementation was correct - the test needed updating
- Understanding the full context prevents over-engineering
